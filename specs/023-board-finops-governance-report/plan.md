# Implementation Plan: Board FinOps & Governance Power BI Report (EULearn / Fabric)

**Branch**: `023-board-finops-governance-report` | **Date**: 2026-07-30 | **Spec**: [spec.md](spec.md)

## Summary

Ship a board-facing Power BI report in the **EULearn** Fabric workspace (`127a12ab…`, F16, tenant `63e6b296…`) that answers the board's recurring FinOps and governance questions: cost per active user per month, model routing, recurring FinOps trend, teacher time, localisation velocity, and DPIA/governance freshness. The report is backed by a **new, dedicated board semantic model** so the existing director reporting stack is left untouched.

## Technical Context

- **Platform**: Microsoft Fabric (EULearn workspace, EU-resident F16 capacity).
- **Auth / identity**: `az` CLI + Fabric REST as `esigwald@microsoft.com` (tenant `63e6b296…`). The Fabric MCP tools authenticate as a different (MSIT) identity that cannot see EULearn — do **not** use them here.
- **Build tooling**: reuse `work/fabric/FabricRest.ps1` (`Invoke-FabricLRO`, `Build-FabricParts`, `New-FabricReport`, `Update-FabricDefinition`) plus a new `New-FabricSemanticModel` helper and a `work/fabric/deploy-board-finops.ps1` builder, mirroring `deploy-director-dashboard.ps1`.
- **Semantic model**: TMDL definition (`.pbism` + `model.tmdl` + `tables/*.tmdl`). All tables are **import-mode inline `#table` fixtures** carrying board-level, non-personal aggregates — no external datasource, so the model always refreshes and needs no gateway/credential binding. Fixture values are derived from the platform's telemetry categories (AI usage/cost from `ask_history`, model mix, teacher Q&A from `teacher_questions`, localisation from `glossary_terms`, and the governance/DPIA register).
- **Report**: Power BI report definition v4.0 (`definition.pbir` `byConnection` → new board model; `report.json` legacy sections/visualContainers format; `.platform`). Built with the same `Textbox`/`Card`/`CatMeasureChart` helpers used for the director dashboard, plus a governance table visual.
- **No personal data**: board fixtures are aggregates only (FR-003).

## AI Act articles touched

- **Art. 9 (risk management)** / **Art. 17 (quality management)**: the report *evidences* governance-review cadence (DPIA freshness, overdue reviews) but does not itself make decisions.
- **Art. 13 (transparency)**: board-level transparency into cost, model routing, and governance health.
- No new high-risk inference is introduced — the report is read-only decision-support with aggregated, non-personal data.

## DPIA delta

- **No new personal-data processing.** The board report consumes only aggregated, non-personal figures. The DPIA register is *referenced* (as data about governance artefacts), not learner personal data. → **No DPIA change required**; the feature instead surfaces DPIA freshness to the board.

## Human-oversight surface

- The report is board decision-support. FinOps actions (model-mix changes, budget) and governance actions (refresh a DPIA) remain human-owned and are executed outside this report. No automation, no grading, no profiling.

## Approach & phases

1. **Model** — author TMDL for five fixture tables + board DAX measures (cost per active user, est cost, active users, model share, teacher hours saved, localisation velocity, days-since-review, overdue reviews).
2. **Report** — author `report.json` builder (KPI cards + trend/routing/localisation/governance visuals) and `definition.pbir`/`.platform`.
3. **Deploy** — `deploy-board-finops.ps1`: create the semantic model (new item) → capture its id → write `definition.pbir` `byConnection` → create the report (new item). Verify existing director items untouched.
4. **Verify** — confirm both items exist in EULearn, report renders, KPIs populate, and `5f98fc5b…` / `f51f6c63…` are unchanged.

## Risks & mitigations

- **Risk**: Accidentally editing the live director model. **Mitigation**: build entirely new items; the deploy script only ever targets the board item ids it creates.
- **Risk**: `report.json` visual schema drift. **Mitigation**: reuse the proven director-dashboard builder helpers and validate JSON round-trip before upload.
- **Risk**: Fixtures diverge from real telemetry. **Mitigation**: FR-007 notes a future live-Postgres variant (out of scope, must not alter the existing model); fixtures are labelled board aggregates.
