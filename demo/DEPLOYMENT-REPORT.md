## 4. Data seed (Stage 5)

Source files packaged under `apps/learner-web/data/` (and synced to the other apps via `apps/_shared/sync.ps1`):
- `curricula/nl-kerndoelen-math-y7.json`, `curricula/de-bildungsstandards-math-y7.json` → table `curricula` (6 rows)
- `glossaries/math-nl-NL.csv`, `glossaries/math-de-DE.csv` → table `glossary_terms` (14 rows)
- `synthetic_learners.csv` → table `learners` (50 rows)

Seeding is idempotent (`ON CONFLICT DO NOTHING`) and runs on every container start. A defensive admin-only endpoint `POST /api/data/reseed` (committed in Stage 5) returns before/after counts and is useful when redeploying against an existing database.

### Stage 5 unblocking notes
- The PostgreSQL `azure.extensions` server parameter was empty on the freshly provisioned server, so `CREATE EXTENSION pgcrypto` (required by `schema.sql` for `gen_random_uuid()`) failed silently and the seed never ran. We set `azure.extensions=PGCRYPTO`, restarted the server, restarted the apps, and schema + seed completed normally on the next container start.
- The flexible server had been auto-stopped for cost reasons; `az postgres flexible-server start` was required before the first reseed attempt.

## 6. Key decisions & lessons learned

- **Run-from-package off, Oryx on.** `azd` defaults to `WEBSITE_RUN_FROM_PACKAGE=1`, which makes wwwroot read-only and skips `npm install`. We override to `WEBSITE_RUN_FROM_PACKAGE=0` + `SCM_DO_BUILD_DURING_DEPLOYMENT=true` so the SCM container extracts the zip and Oryx installs dependencies. This is the only way `express` (and friends) become importable on B1.
- **Postgres extensions allow-list.** Azure Flexible Server requires `azure.extensions` to be populated and the server restarted before `CREATE EXTENSION` succeeds, even for `pgcrypto`. Bicep should set this at provision time in a follow-up iteration.
- **Container warmup ≈ 90 s.** On a B1 plan with VNet integration + KV references, `/api/health` is unreachable for ~90 s after a restart. Acceptance probes need `-TimeoutSec 60–90`, not 20.
- **Auth-gated static assets.** The ONNX model is served behind the same session cookie as the rest of the app, so smoke tests `POST /api/auth/login` before `GET /models/learner.onnx`. This is by design — the model is treated as protected IP, not as a public asset.
- **Adaptive UI simplification (Checkpoint A).** The original self-assessment flow confused users. We rewrote it as a 2-column layout: column 1 is the example item (question + difficulty + predicted P(correct)%), column 2 is the user's answer (text input + ✓ / ✗ + tip). This is the user-visible front of the ONNX picker that drives criterion #4.
- **Cost.** Steady-state hourly burn is dominated by APIM Developer (~€0.05/h), AOAI (pay-per-token, near zero idle), Postgres Burstable B1ms (~€0.02/h), App Service B1 (~€0.02/h). Total demo cost during build ≈ €15–25. Stop the Postgres server and `az webapp stop` the four sites when not demoing to drop to APIM-only.
